# Modern Dark SaaS — Developer App Theme

**Theme category:** Modern SaaS / Minimalist Developer Tool  
**Version:** 1.0

---

## 1. Theme Overview

Create a modern, premium-looking application theme for a professional code editor.

The visual direction takes inspiration from contemporary SaaS products and developer tools such as:

- T3 Code
- Arion
- Onyx
- Linear
- Raycast

The theme should combine the polished appearance of modern SaaS applications with the functionality and information density of professional developer tools.

The overall aesthetic should feel:

- Modern and polished.
- Minimal but not empty.
- Technical without looking outdated.
- Elegant and visually balanced.
- Comfortable for extended use.
- Consistent across every screen and component.
- Professional rather than overly decorative.

The objective is to establish a cohesive visual identity that makes the entire application feel like a premium developer product.

---

## 2. Core Design Principles

### 2.1 Minimalism

Keep the interface clean and visually focused.

- Avoid unnecessary visual elements.
- Avoid excessive borders and separators.
- Use spacing to establish visual separation.
- Prefer subtle distinctions between surfaces.
- Keep toolbars and navigation compact.
- Avoid excessive icons, labels and decorative elements.
- Do not place every element inside a separate container.

Minimalism should improve clarity, not remove useful information.

### 2.2 Visual Hierarchy

Establish a clear hierarchy throughout the application.

Use three levels of visual emphasis:

1. **Primary:** Main editor, active workspace, important actions and selected elements.
2. **Secondary:** Navigation, file explorer, tabs, panels and supporting controls.
3. **Tertiary:** Metadata, timestamps, shortcuts, descriptions and secondary information.

The most important elements should naturally attract attention without relying on excessive visual decoration.

### 2.3 Consistency

All application components should follow the same visual language.

Maintain consistent styling across:

- Buttons.
- Inputs.
- Dropdowns.
- Menus.
- Dialogs.
- Panels.
- Navigation.
- Tabs.
- Tooltips.
- Notifications.
- Context menus.

Components should feel like parts of the same product rather than independent UI elements.

### 2.4 Functionality First

The theme must preserve the usability of a professional code editor.

- Prioritize code readability.
- Maintain clear visual hierarchy.
- Keep important controls accessible.
- Avoid unnecessary visual distractions.
- Preserve comfortable spacing and interaction areas.
- Ensure the interface remains practical during extended coding sessions.

## 3. Typography

Typography should be modern, clean and highly readable.

Use a contemporary sans-serif typeface for the application interface.

Recommended typefaces:

- Inter
- Geist
- Manrope

Use a monospace typeface for code and technical information.

Recommended typefaces:

- JetBrains Mono
- Geist Mono
- Berkeley Mono

### Typography Hierarchy

| Element | Suggested size | Weight |
|---|---|---|
| Main headings | 20px | 600 |
| Section headings | 14px | 600 |
| Body text | 13px | 400 |
| Secondary text | 12px | 400 |
| Small metadata | 11px | 400 |
| Code editor | 13–14px | 400 |

### Typography Guidelines

- Maintain a consistent type scale.
- Use font weight to establish hierarchy.
- Avoid excessive font-size variations.
- Keep supporting information visually understated.
- Use consistent line heights.
- Avoid overly bold interface typography.
- Maintain excellent readability at smaller sizes.

---

## 4. Application Surface Styling

Establish a consistent visual treatment for all application surfaces.

The theme should support the existing application structure, including:

- Top navigation bar.
- Activity sidebar.
- File explorer.
- Main editor workspace.
- Editor tabs.
- Secondary panels.
- Terminal.
- Status bar.
- Settings.
- Dialogs.
- Dropdowns.
- Context menus.
- Command palette.
- AI assistant panel.

### Surface Hierarchy

Create visual depth through subtle differences in surface elevation.

Use a consistent distinction between:

1. Main application surfaces.
2. Navigation and sidebar surfaces.
3. Secondary workspace panels.
4. Elevated interface elements.
5. Hovered and selected elements.

Avoid excessive outlines and unnecessary nested containers.

Surfaces should feel connected while remaining visually distinguishable.

---

## 5. Layout and Spacing

Use a structured, balanced and compact application layout.

The theme should complement the existing application layout without requiring structural changes.

### General Guidelines

- Use consistent spacing between related elements.
- Maintain clear separation between unrelated sections.
- Keep navigation compact.
- Avoid oversized headers and toolbars.
- Maintain consistent alignment.
- Use whitespace intentionally.
- Avoid unnecessarily large padding.
- Keep the main editor visually dominant.

### Spacing Scale

Use a consistent spacing system based on multiples of 4px.

| Token | Size | Usage |
|---|---|---|
| XS | 4px | Small internal gaps |
| SM | 8px | Compact component spacing |
| MD | 12px | Standard component spacing |
| LG | 16px | Section spacing |
| XL | 24px | Larger content separation |
| 2XL | 32px | Major layout separation |

Spacing should be consistent throughout the application.

---

## 6. Navigation Styling

Navigation should feel compact, modern and unobtrusive.

### Guidelines

- Use consistent icon dimensions.
- Keep inactive navigation elements visually understated.
- Make active states immediately recognizable.
- Use subtle hover feedback.
- Maintain consistent alignment.
- Avoid excessive separators.
- Use tooltips for icon-only controls.
- Keep navigation labels readable and appropriately sized.

Navigation elements should feel lightweight without becoming difficult to discover.

---

## 7. File Explorer Styling

The file explorer should feel clean, organized and lightweight.

### Guidelines

- Maintain a clear folder hierarchy.
- Use consistent file icon sizing.
- Keep folder indentation uniform.
- Use subtle indentation guides.
- Establish clear selected-file states.
- Use understated hover effects.
- Keep file names readable.
- Avoid excessive separators.
- Keep folder and file rows compact.

The file explorer should feel integrated into the application rather than like a separate file-management tool.

---

## 8. Editor Tabs

Editor tabs should have a compact and polished appearance.

### Guidelines

- Use consistent tab dimensions.
- Maintain clear active and inactive states.
- Use subtle surface differentiation.
- Keep file icons consistent.
- Use understated unsaved-change indicators.
- Display close controls on hover where appropriate.
- Avoid oversized tabs.
- Avoid excessive borders and separators.

The tab system should remain visually lightweight while making it easy to identify the active file.

---

## 9. Code Editor Appearance

The code editor should remain the primary visual focus.

### Code Area

- Use a highly readable monospace font.
- Maintain comfortable line height.
- Keep line numbers subtle.
- Use minimal indentation guides.
- Maintain clear cursor visibility.
- Make selections easy to distinguish.
- Keep syntax highlighting balanced.
- Avoid distracting background effects.

### Syntax Highlighting

Syntax highlighting should be expressive but restrained.

Use distinct visual treatments for:

- Keywords.
- Functions.
- Strings.
- Variables.
- Numbers.
- Comments.
- Types.
- Operators.
- Constants.

Avoid excessive saturation and unnecessary visual contrast.

The syntax highlighting should complement the overall application theme without competing with the code itself.

### Editor Features

Preserve the existing visual functionality of:

- Autocomplete.
- IntelliSense.
- Error highlighting.
- Code folding.
- Multiple cursors.
- Find and replace.
- Go to definition.
- Quick actions.
- Minimap, if supported.

---

## 10. Bottom Panel and Terminal

Bottom panels should follow the same visual language as the rest of the application.

This includes:

- Terminal.
- Problems.
- Output.
- Debug console.
- Build logs.

### Guidelines

- Use compact panel headers.
- Maintain consistent tab styling.
- Make active panel states clear.
- Use subtle separators.
- Keep panel controls understated.
- Maintain consistent typography.
- Preserve comfortable terminal readability.
- Allow existing panels to be collapsed and resized.

Avoid excessive visual containers around terminal output.

---

## 11. AI Assistant Styling

If the application includes AI functionality, the assistant should feel like a native part of the editor.

### Guidelines

- Use consistent typography.
- Keep message layouts compact.
- Avoid oversized chat bubbles.
- Use subtle separation between messages.
- Maintain readable code blocks.
- Use consistent button styling.
- Keep model selectors compact.
- Make execution states easy to understand.
- Use consistent attachment and context indicators.
- Keep conversation history visually organized.

The AI interface should feel like another part of the developer environment, not a separate application embedded inside it.

## 12. Component Design System

All reusable components should follow consistent styling rules.

### Buttons

**Primary buttons**
- Clear visual emphasis.
- Compact dimensions.
- Consistent typography.
- Subtle interaction feedback.

**Secondary buttons**
- Understated appearance.
- Consistent alignment.
- Clear hover states.

**Ghost buttons**
- Minimal visual footprint.
- No unnecessary permanent outlines.
- Subtle hover feedback.

### Inputs

- Consistent dimensions.
- Clear text alignment.
- Subtle borders.
- Distinct focus states.
- Comfortable internal spacing.
- Consistent placeholder styling.

### Dropdowns and Popovers

- Compact menus.
- Consistent item spacing.
- Clear hover states.
- Distinct selected states.
- Subtle elevation.
- Consistent corner treatment.

### Cards and Panels

- Use containers only when they provide meaningful grouping.
- Maintain consistent internal spacing.
- Avoid excessive nesting.
- Keep visual separation subtle.

### Border Radius

| Component | Radius |
|---|---|
| Small controls | 5px |
| Buttons | 6px |
| Inputs | 6px |
| Menus | 8px |
| Dialogs | 12px |
| Larger containers | 10px |

Maintain consistent corner styling throughout the application.

---

## 13. Visual Effects

Use visual effects carefully to create depth and polish.

### Recommended

- Subtle shadows.
- Restrained gradients.
- Soft surface transitions.
- Minimal background highlights.
- Smooth hover animations.
- Subtle elevation changes.
- Consistent focus indicators.

### Avoid

- Excessive glassmorphism.
- Heavy blur effects.
- Strong neon effects.
- Oversized glowing borders.
- Excessive gradients.
- Heavy shadows around every component.
- Unnecessary decorative animations.
- Excessive background textures.

The theme should feel refined through its details rather than through visual effects.

---

## 14. Interaction States

Every interactive component should have consistent visual states.

Required states:

- Default.
- Hover.
- Active.
- Selected.
- Focused.
- Disabled.
- Loading.
- Error.
- Success.

### Animation Guidelines

Use short and subtle transitions.

Recommended duration: 120–180ms.

Apply transitions consistently to:

- Buttons.
- Dropdowns.
- Tooltips.
- Menus.
- Dialogs.
- Navigation elements.
- Panel interactions.
- Selection feedback.

Avoid animations that distract from coding or slow down common workflows.

Respect reduced-motion preferences.

---

## 15. Responsive Styling

The theme should remain visually consistent across different application window sizes.

### Guidelines

- Preserve clear visual hierarchy at smaller widths.
- Maintain readable typography.
- Avoid unnecessary content compression.
- Keep important controls accessible.
- Preserve consistent spacing.
- Ensure panels remain visually coherent.
- Avoid breaking component alignment.

Desktop remains the primary target because this is a professional code editor.

## 16. Accessibility

Maintain accessibility throughout the theme.

Requirements:

- Readable typography.
- Sufficient text contrast.
- Clearly visible focus states.
- Consistent interactive feedback.
- Distinguishable selected states.
- Tooltips for icon-only controls.
- Clear error and success indicators.
- Keyboard-friendly navigation.
- Reduced-motion support.

## 18. Final Design Direction

The final theme should combine:

- Modern SaaS design principles.
- Minimalist developer-tool aesthetics.
- Technical and functional interface styling.
- Clean typography.
- Consistent spacing.
- Subtle surface differentiation.
- Refined component styling.
- Understated visual effects.
- Consistent interaction states.

### Core Design Philosophy

**Premium through simplicity, precision and consistency.**

Every component should feel intentional. Nothing should be visually louder than necessary.

The final application should feel like a contemporary professional developer tool, taking inspiration from products such as Linear, Raycast, T3 Code, Arion and Onyx.

**Theme scope:** Visual styling and presentation only. The application's existing functionality, architecture, workflows and layout behaviour should remain intact.

**Color configuration:** All color values, palettes and semantic color assignments are managed separately by the application's color theme. This app theme must not hardcode or override those values.
